# F10.3 — Admin UX: Branding, Access Control, Live Preview, Reorder, Stats, Todo

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Payload CMS admin panel usable for non-technical portfolio owners: custom branding, access control (owners see only their data), live theme preview, block reorder UI, page view stats, and a personal todo list.

**Architecture:**
- Branding: custom Logo component registered in `payload.config.ts admin.components`
- Access control: field-level and collection-level access functions in Payload config
- Live preview: Payload built-in `admin.livePreview` in Portfolios collection, pointing to `/(portfolio)/dev/[slug]`
- Block reorder: custom client component added as a Payload admin view
- Stats: Vercel Analytics on the portfolio frontend + simple `viewCount` field on Portfolios
- Todo: new `Todos` Payload collection

**Prerequisite:** None (independent of F10.1 and F10.2, but works best after F10.2 is done).

**Tech Stack:** Payload CMS 3 (custom components, access control, livePreview), `@vercel/analytics`, React (custom admin component), TypeScript.

### Task 2: Access Control — owners see only their portfolio (A10.2)

**Files:**
- Modify: `platform/src/payload/collections/Portfolios.ts`
- Modify: `platform/src/payload/collections/Blocks.ts`

Access control rules:
- `superadmin` / `admin` — full access to everything
- `owner` — can only read/update their own portfolio, can only read/update/create blocks for their portfolio

- [ ] **Step 1: Add access control to Portfolios.ts**

In `platform/src/payload/collections/Portfolios.ts`, add `access` block:

```typescript
import type { CollectionConfig } from "payload";

export const Portfolios: CollectionConfig = {
  slug: "portfolios",
  admin: {
    useAsTitle: "subdomain",
  },
  access: {
    read: ({ req }) => {
      if (!req.user) return true; // public can read (for sitemap etc.)
      if (req.user.role === "superadmin" || req.user.role === "admin") return true;
      // owners see only their own
      return { owner: { equals: req.user.id } };
    },
    create: ({ req }) => {
      return req.user?.role === "superadmin" || req.user?.role === "admin";
    },
    update: ({ req }) => {
      if (!req.user) return false;
      if (req.user.role === "superadmin" || req.user.role === "admin") return true;
      return { owner: { equals: req.user.id } };
    },
    delete: ({ req }) => {
      return req.user?.role === "superadmin" || req.user?.role === "admin";
    },
  },
  fields: [
    // ... (keep all existing fields unchanged)
  ],
};
```

Keep all existing fields as-is.

- [ ] **Step 2: Add access control to Blocks.ts**

In `platform/src/payload/collections/Blocks.ts`, add `access` block at the top of the config:

```typescript
access: {
  read: ({ req }) => {
    if (!req.user) return true;
    if (req.user.role === "superadmin" || req.user.role === "admin") return true;
    // owners: only blocks for their portfolios
    // Payload doesn't support nested relationship filters in access — use depth instead
    // For now: owners can read all blocks (filter by portfolio in UI)
    return true;
  },
  create: ({ req }) => Boolean(req.user),
  update: ({ req }) => Boolean(req.user),
  delete: ({ req }) => {
    return req.user?.role === "superadmin" || req.user?.role === "admin";
  },
},
```

Note: Full per-portfolio access control for Blocks requires custom access logic that queries the portfolio ownership. The above is a simplified version — owners can read/edit all blocks but cannot delete. Tighten in Faza 6 (security review).

### Task 3: Live Theme Preview (A10.9)

**Files:**
- Modify: `platform/src/payload/collections/Portfolios.ts`

Payload's `admin.livePreview` shows the portfolio in an iframe while editing. The `dev/[slug]` route already exists.

- [ ] **Step 1: Add livePreview to Portfolios collection**

In `platform/src/payload/collections/Portfolios.ts`, inside the collection config add:

```typescript
admin: {
  useAsTitle: "subdomain",
  livePreview: {
    url: ({ data, req }) => {
      const baseUrl = req.headers.get("x-forwarded-host")
        ? `https://${req.headers.get("x-forwarded-host")}`
        : process.env.NEXT_PUBLIC_APP_URL ?? "http://localhost:3000";
      const slug = data.subdomain ?? "";
      return `${baseUrl}/dev/${slug}`;
    },
  },
},
```

### Task 6: Todo List per User (A10.8)

**Files:**
- Create: `platform/src/payload/collections/Todos.ts`
- Modify: `platform/payload.config.ts` — register Todos collection

- [ ] **Step 1: Create Todos collection**

Create `platform/src/payload/collections/Todos.ts`:

```typescript
import type { CollectionConfig } from "payload";

export const Todos: CollectionConfig = {
  slug: "todos",
  admin: {
    useAsTitle: "title",
    defaultColumns: ["title", "done", "portfolio", "updatedAt"],
    description: "Osobista lista zadań — widoczna tylko dla Ciebie",
  },
  access: {
    read: ({ req }) => {
      if (!req.user) return false;
      if (req.user.role === "superadmin" || req.user.role === "admin") return true;
      return { owner: { equals: req.user.id } };
    },
    create: ({ req }) => Boolean(req.user),
    update: ({ req }) => {
      if (!req.user) return false;
      if (req.user.role === "superadmin" || req.user.role === "admin") return true;
      return { owner: { equals: req.user.id } };
    },
    delete: ({ req }) => {
      if (!req.user) return false;
      if (req.user.role === "superadmin" || req.user.role === "admin") return true;
      return { owner: { equals: req.user.id } };
    },
  },
  fields: [
    {
      name: "title",
      type: "text",
      required: true,
    },
    {
      name: "done",
      type: "checkbox",
      defaultValue: false,
    },
    {
      name: "portfolio",
      type: "relationship",
      relationTo: "portfolios",
      admin: {
        description: "Opcjonalne — powiąż zadanie z konkretnym portfolio",
      },
    },
    {
      name: "owner",
      type: "relationship",
      relationTo: "users",
      required: true,
      admin: {
        description: "Właściciel zadania (wypełniane automatycznie)",
        readOnly: true,
      },
    },
    {
      name: "notes",
      type: "textarea",
    },
  ],
  hooks: {
    beforeChange: [
      ({ req, data }) => {
        if (req.user && !data.owner) {
          data.owner = req.user.id;
        }
        return data;
      },
    ],
  },
};
```
